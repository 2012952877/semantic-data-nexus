# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Data analysts, analytics engineers, and governance-minded business operators who need to ask business questions while retaining a reviewable, deterministic execution trail.

## Product Purpose

Semantic Nexus turns natural-language questions into governed analytical runs. Success means a newcomer can understand what will be queried, follow every execution stage, inspect the typed plan and lineage, and act on either a result or an actionable diagnostic without exposing secrets or relying on a live backend.

## Positioning

The model proposes a typed Semantic Query Graph (SQG); it never directly executes model-generated SQL. Compilation, optimization, execution, and result commitment remain explicit, inspectable stages.

## Operating Context

Users work in a browser across an ask workspace, run history and detail views, an ontology explorer, and read-only component status. The M0 experience is fully backed by deterministic synthetic regional-sales fixtures and a strict mock client contract.

## Capabilities and Constraints

- Vue 3, TypeScript, Vite, and stable Vue Router deep links.
- Typed contracts cover SQG summaries, runs, stages, plan nodes, results, lineage, and ontology.
- Success, empty-result, failure, cancellation, retry, and loading states are required.
- Run history persists only in localStorage with an explicit schema version.
- No real backend dependency, secret fields, proprietary assets, private data, or direct execution of generated SQL.
- Chinese-first interface with concise plain-language explanations and progressive disclosure for technical details.

## Brand Commitments

The product name is **Semantic Nexus**. The voice is calm, precise, and transparent: explain governance and technical terms without hype, gamification, or unexplained jargon.

## Evidence on Hand

Only the issue brief and repository description are authoritative. All demonstrations must use clearly synthetic regional-sales data; no customer claims, benchmarks, screenshots, or production connectivity may be fabricated.

## Product Principles

1. Governance is visible at the moment of action.
2. Every run is understandable from question to committed result.
3. Plain language leads; technical detail remains available on demand.
4. Failure and empty data are explained as product states, not dead ends.
5. Mock behavior must honor the same typed boundary as a future HTTP client.

## Accessibility & Inclusion

Meet WCAG-conscious contrast and keyboard/focus expectations, use semantic regions and controls, preserve useful labels, and support responsive desktop, tablet, and mobile layouts.
